# Content Studio

A standalone developer application for managing, editing, validating, inspecting and
balancing the authored game data of **In The Dungeons We Die**. It is a permanent dev tool:
it lives in this repository but the game and its documentation do not reference it, and it
ships with nothing.

```
dotnet run --project ContentStudio
```

That starts a local server on `http://127.0.0.1:5590` and opens the UI in your browser.
Flags: `--port 1234`, `--no-browser`. To produce a `ContentStudio.exe`:

```
dotnet publish ContentStudio -c Release -o ContentStudio/publish
```

(`ContentStudio/publish/ContentStudio.exe` — framework-dependent; add `-r win-x64 --self-contained`
for a machine without .NET.)

On first launch it walks up from its own location looking for a folder containing `game/data`,
so running it from inside the repo needs no setup. The chosen project is remembered in
`%APPDATA%\ContentStudio\settings.json` and can be changed from the project chip in the top bar.

## What it is

- **Editors for every authored content type** (the 35 folders under `game/data/`), with
  schema-driven forms generated by reflecting the Core definition classes — the same classes
  `DataStore<T>` deserializes into, so the forms cannot drift from what the game reads.
  Reference fields are searchable pickers, dictionaries get vocabulary-aware key pickers
  (properties, lanes, damage types, essence keys…), lists reorder, and every record also has
  a **Raw JSONC** tab.
- **Comment-preserving editing.** The authored files are full of design-note comments; the
  tool patches files surgically (span-tracking JSONC parser + minimal text edits) instead of
  re-serializing them. Reordering records carries their comments along; deleting a record
  removes its attached comment but never a section header.
- **Validation** = the game's own `ContentValidator` (the rules that gate startup) + per-record
  "can the game parse this" checks + studio-only checks the game cannot express: unknown JSON
  fields (which `DataStore<T>` silently ignores) and id-shaped strings that resolve to nothing.
- **Safety**: edits stay in memory until an explicit Save; saves are atomic and preceded by
  timestamped backups (`%LOCALAPPDATA%\ContentStudio\backups`, restorable in-app); a file
  watcher reloads clean files when Claude/an editor/git changes them and raises a conflict
  (with a diff and Reload/Keep choices) when you also have unsaved edits; deleting shows what
  references the record first; session-wide undo/redo (Ctrl+Z / Ctrl+Y).
- **Dependency explorer** built from the actual JSON (any string value that matches an
  existing id is an edge), both directions, plus per-record reference lists in the inspector.
- **Balance Studio** (analysis only, never mutates): resolved-enemy tables and EHP via the
  real `ActorResolver` + hit-pipeline math, resistance/vulnerability heatmaps, move economics
  with anti-DPS-myopia columns, the material property space with a query language
  (`hardness > 70 and tag = form:metal`), profession XP/hour and time-to-99 timelines, loot
  expected value per table and **"where does this item drop"** across every enemy/location/
  action, orphan-loot detection, and z-score outlier warnings.
- **AUTHORED vs RESOLVED**: enemy records have a Resolved tab showing the family + role +
  actor fold with per-value provenance; loot tables have a Drop Analysis tab; realms have a
  read-only graph view.
- `Ctrl+K` searches everything; `Ctrl+S` saves all.

## Layout

```
ContentStudio/
  Program.cs               hosting, static UI, browser launch
  Api/ApiEndpoints.cs      every HTTP endpoint (thin handlers)
  Services/                ContentTypeRegistry (folder↔Core-type map, mirrors ContentLoader.LoadAll),
                           ContentWorkspace (in-memory files/records, CRUD, save/conflicts),
                           GameBundleService (builds a real ContentBundle from unsaved state),
                           ValidationService, ReferenceIndexService, SchemaGenerator+SchemaOverrides,
                           VocabularyService, BackupService, FileWatcherService, SseHub, StudioState
  Analysis/                EnemyAnalysis, MoveAnalysis, ProfessionAnalysis, LootAnalysis,
                           BalanceWarningAggregator
  Infrastructure/Jsonc/    the span-tracking JSONC parser/writer/patcher (comment preservation)
  Validation/              UnknownFieldScanner
  wwwroot/                 the UI — plain ES modules, no build step, no npm, no CDN
  Tests/                   xunit suite incl. fences that run the parser/patcher against every
                           shipped content file (identity diff must produce zero edits)
```

## Adding a content type later

When the game grows a folder + `ContentBundle` store, give Content Studio one entry in
`Services/ContentTypeRegistry.cs` and one line in `Services/GameBundleService.cs` (mirroring
the new `ContentLoader.LoadAll` line). Everything else — schema, editors, search, validation,
references — derives automatically. Optional polish: a layout in `wwwroot/js/editor.js`
(`EDITOR_LAYOUTS`) and reference/vocabulary hints in `Services/SchemaOverrides.cs`.

## Boundaries this tool respects

- It never writes anywhere except `game/data/**` (and its own settings/backups outside the repo).
- It never edits definitions the game generates at runtime (emergent materials/equipment live
  in the save file, which the tool does not touch).
- Balance analysis never changes values — it only points.
